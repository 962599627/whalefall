# 参考项目分析：TVBoxOSC / 友商（取其精华，去其糟粕）

> 对象：[j4Uq/TVBoxOSC](https://github.com/j4Uq/TVBoxOSC)（CatVod 分支，18k★，Java/Android）、[XiaochangChang/AVBox](https://github.com/XiaochangXu/AVBox)（MD3 版）、上游开源 Flutter 版（友商同源）。
> 目的：给鲸落下一轮功能取舍提供依据。

## 一、值得借鉴（精华）

| # | 设计 | 说明 | 我们的差距 | 工作量 |
|---|---|---|---|---|
| 1 | **播放器内核切换**（Exo / IJK / 系统） | 不同源/编码兜底，失败可切内核 | 目前固定播放器，失败只能换源 | M |
| 2 | **画面缩放/纵横比记忆** | 裁剪/适应/拉伸，按影片记住 | 有切换但未记忆、无按片记忆 | S |
| 3 | **设置项分层清晰**：数据源显示 / 窗口预览（小窗）/ 按钮位置 / 后台播放 / 系统播放器 / DNS / 聚搜 / 备份还原 / 重置 / 关于 | 每项独立开关，默认值合理 | 部分有（备份/聚搜），缺窗口预览、按钮位置、DNS、后台播放 | M |
| 4 | **配置地址历史 + 备份还原** | 换源/回滚方便 | 历史刚做（1.8.7），备份已有 | 已完成 |
| 5 | **多源聚合搜索 + 来源标记 + 手选来源** | 减少重复结果与「点了不能播」 | 1.8.1 已做基础版（合并/长按选源） | 已做，待验收 |
| 6 | **关于/免责声明 + 开源致谢** | 合规、可信；友商弹窗就是这类文本 | 关于页无免责声明与 credits | S |
| 7 | **失败自动换源/换线路** | 播放失败自动尝试下一线路 | 目前手动切 | M |
| 8 | **直播频道收藏/EPG 节目单** | TV 场景刚需 | 无 EPG，收藏基础 | M |

## 二、不学（糟粕）

- **不内置/不聚合灰色源**：保持「用户自带配置源」的边界（TVBoxOSC 本身不提供内容，这点要学）。
- **不做广告、不做诱导分享、不堆「解锁/福利」入口**。
- **不堆几十个无说明的开关**：每个设置项必须有清晰文案与默认值。
- **不依赖插件私有 hack**（反编译/改 jar 之类），兼容性差且不可维护。
- **不要仿「窗口预览」那种容易与小窗/画中画冲突的功能**，除非先做 PiP 生命周期设计。

## 三、建议下一轮优先做（按性价比）

1. **S**：关于页补免责声明 + 开源致谢（TVBoxOSC/上游 MarcoMovie/AList/OpenList）。
2. **S**：画面缩放比例按影片记忆 + 播放页显示当前比例。
3. **S**：设置文案/分组梳理（对齐友商「数据源显示/系统播放器/聚搜/备份还原/重置/关于」）。
4. **M**：失败自动换源（当前线路失败→尝试同片其它线路/来源，带提示）。
5. **M**：播放器内核切换（Exo/IJK/系统）+ 失败提示。
6. **M**：后台播放（音频持续）+ 通知控制（与 PiP 一起设计）。
7. **M**：直播 EPG/收藏增强（依赖源是否提供节目单）。
8. **M**：窗口预览/小窗（可选，先与 PiP 二选一，避免生命周期冲突）。

## 四、结论
取：设置分层、内核切换、比例记忆、失败换源、免责声明与致谢、EPG。
去：内置源/广告/诱导/无说明开关/插件 hack/重复的小窗形态。
