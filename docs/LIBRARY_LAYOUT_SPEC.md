# 片库（观看历史 / 我的收藏 / 我的下载）· 三端响应式布局规范

> 适用范围：`MobileShell.renderMyTab()` 与 `MyListAdapter`（`android/src/main/java/com/whalefall/movie/MobileShell.java`），
> 含「观看历史 / 我的收藏 / 我的下载」三个页签与右上「清空历史」。
> 视觉 token 唯一依据：`docs/WHALEFALL_DESIGN_SYSTEM.md`；断点/方向策略沿用
> `docs/TV_LIVE_RESPONSIVE.md`。**不新增颜色**，字号只用设计系统 §2 的七档：
> 24 / 17 / 16 / 15 / 13 / 11.5 / 10.5 sp。
> 本文只定义规范，不含代码改动。

---

## 0. 结论先看

1. **手机 = 列表行，平板/TV = 自适应网格**。
   - `<600`：保留竖排列表行（缩略图 56×80 + 标题/进度 + 删除），一屏信息密度高；
   - `600–839`：3 列海报网格（竖屏平板）；
   - `840–1079`：4 列；`≥1080`：5 列；TV：4 列 + 遥控焦点。
2. **平板横屏/TV 用「顶部页签 + 自适应网格」，不用「左侧分类/统计栏」**。
   理由：① 页签只有 3 个、切换低频，不值得占 168–176dp 固定宽度；② 左侧再加一条栏会和
   `MobileShell` 全局右侧竖导航栏（72dp）形成左右双栏夹击，网格可用宽度只剩 ~500dp；
   ③ 统计信息用标题右侧一行 11.5sp 文案即可（「共 12 部 · 本周新增 3」），不需要独立栏。
3. **卡片宽度只由网格列数决定，永远不由标题决定**：
   `GridLayoutManager` + item `MATCH_PARENT`；标题固定 2 行高（手机列表 1 行），
   超出省略号。这样长标题不会撑满，也不会出现「一条宽一条窄」。
4. **封面统一 2:3**（宽:高 = 2:3，即高 = 宽×1.5）；平板/TV 网格卡片 = 封面 + 固定标题区 +
   固定 meta 区，三块高度固定 → 所有卡片等高。
5. 现有实现要收敛的点：行卡片背景 `#CC1E3557/#CC17294A` 不是 token → 改 `GLASS_FILL` + `STROKE`；
   删除红 `#EF4444` → `DANGER #FF6B81`；页标题 22sp → `TYPE_CLOCK` 24sp；页签激活白底 →
   `ACCENT` 渐变 + 深色字；平板下缺列数计算（当前全宽一行）→ 本规范补 `spanCount` 公式。

**现状截图问题 → 本规范对应章节**

| 现状问题 | 根因 | 对应 |
| --- | --- | --- |
| 平板横屏内容挤在左侧一列、右侧大片空白 | 页面只有单列 `LinearLayout` 行，行宽为全宽但内容左对齐；没有用 `Wc` 减全局右导航栏 | §1 可用宽度公式、§2 T2/T3 网格 |
| 卡片宽度不统一、长标题那条被撑满 | 行内标题列 `weight=1`，行宽全宽、无最大宽；标题未固定行数与高度 | §4.3 等高规则、§5 对齐规则 |
| 手机/平板/TV 无断点规则 | 只按 16dp 边距一套布局 | §1/§2 五档断点 |
| 平板右侧被全局导航栏挤压 | 内容全宽绘制，未扣 `railW` | §1.1、§6 |

## 1. 断点与可用宽度（先扣掉全局导航）

### 1.1 全局导航占位（现状）

- `MobileShell.render()`：`W ≥ 640dp` 时启用**右侧竖导航栏**（`railWrap` 内边距 8+12dp，
  导航条宽 `72 × navScale`；navScale 100% 时约 **92dp**）；`W < 640` 时用底部悬浮 Dock。
- 片库页在 `contentContainer` 内，所以：

```
railW   = (W >= 640) ? (8 + 12 + round(72 * navScale)) : 0      // 100% 时 = 92dp
Wc      = W - railW                                              // 片库可用宽度
content = Wc - sidePad * 2
```

> 注意：平板/大平板/TV 也有右侧全局导航栏，**计算列数必须用 `Wc`，不能用 `W`**；
> 这是当前「平板横屏内容挤在左侧」的隐性原因之一（行宽用了全宽、又只放一个左对齐信息块）。

### 1.2 断点表

| 断点 | 判定 | 典型 W（窗口） | Wc（扣右栏） | 布局 | 列数 |
| --- | --- | --- | --- | --- | --- |
| `PHONE` | `W < 600`（且 `formFactor==PHONE`） | 390 | 390（底部 Dock） | 列表行 | 1 |
| `T1` | `600 ≤ W < 840` | 640（平板竖屏） | 548 | 网格 | **3** |
| `T2` | `840 ≤ W < 1080` | 960（平板横屏） | 868 | 网格 | **4** |
| `T3` | `W ≥ 1080` | 1080+ | ≥988 | 网格 | **5** |
| `TV` | `isTvDevice()` | 960×540 | 868 | 网格 + 焦点 | **4** |

方向策略沿用 `TV_LIVE_RESPONSIVE.md` §1.2：手机锁竖屏、平板不强制、TV 横屏；
断点只随宽度重排，不因旋转固定某一形态重新计算方向。

### 4.3 长标题截断与等高规则

1. 标题固定 2 行高（手机列表 1 行），`maxLines` 固定，**永远不允许 wrap_content 撑高**。
2. 标题区高度写死（42/48dp），文字行高 1.35；两行放不下就省略，第三行不出现。
3. 卡片高度 = 封面高 + 标题区高 + 4dp + meta 区高 + 内边距，全卡片统一，
   因此同一行内任意两条标题长度都不会造成高度差。
4. 列表行（手机）：标题列固定 `width=0 weight=1`，右侧操作按钮固定宽 56dp，标题永不撑宽整行。
5. 不使用 `autoSizeText`；不把标题放进水平 weight 变化的容器里混排。

## 5. 对齐规则（避免长标题撑满 / 宽度不一致）

1. **网格内**：所有 item 用 `GridLayoutManager` 的 span 均分；item 根 `MATCH_PARENT`；
   卡片内部封面 `MATCH_PARENT` 定高；标题/meta 固定高。宽度只来自 span，不来自内容。
2. **列表内**：行宽 = `content`（Wc − 2×sidePad）；文字列 `weight=1`，右侧操作固定 56dp；
   标题单行省略。禁止让文字列 `wrap_content`。
3. **横向与网格混排**（如未来加「继续观看」横向 rail）：横向 rail 的卡片宽度**复用同一公式**
   （见 §8），并用 `paddingStart=sidePad / paddingEnd=sidePad`、`clipToPadding=false`，
   让第一张卡片与网格第一列左缘严格对齐；rail 的 `gapH` 与网格一致，不另设 224dp 之类魔法值。
4. **页头对齐**：标题、统计、页签、清空按钮的左右基线 = `sidePad`；页签行的首个 pill 与标题左缘对齐。
5. **下载列表**（列表型内容）：最大宽 **760dp**，从 `sidePad` 左对齐（不居中，避免和页头右缘错位）；
   超过 760 时右侧留空，但行内信息不拉伸。
6. 统计文案/清空按钮：与标题同一行时右侧用固定宽度，不参与 flex；空间不足时统计先省略。

## 6. 底部 Dock / 系统安全区避让

| 场景 | 规则 |
| --- | --- |
| PHONE（底部 Dock） | Dock 高 64 + 底距 16；片库内容底部留白 **106dp**（Dock 不遮挡卡片与删除按钮） |
| 平板/TV（右侧竖导航栏） | 内容已由 `contentContainer` 让出 railW（≈92dp）；片库自身右边距只再加 `sidePad`，**不要重复减一次 rail** |
| 状态栏 | PHONE `statusBar + 10`；平板 `statusBar + 12`；TV 用 overscan 18dp |
| 底部系统栏/手势条 | PHONE 底部再加 `max(navBarInset, 24)`；平板 edge-to-edge（页面底部 24dp）；TV 无 |
| 刘海/挖孔 | 顶部取 `max(statusBarInset, cutoutTop)`；页头不进入挖孔区 |
| 键盘/搜索 | 片库页无输入框，无 IME 避让 |
| 全屏播放返回 | 回到片库时保持原页签与滚动位置（`mySubTab` 已记忆）；Dock 恢复 |

## 7. TV 焦点顺序与焦点框

1. 焦点链（内容区）：
   ```
   页签行（首个焦点 = 当前页签）
     → 清空历史（仅历史页签）
     → 网格：第 1 行第 1 张卡片（或上次观看的卡片）
     → 网格内 左右移动列、上下移动行
     → 网格最右列再按右 → 全局右侧导航栏（交给 MobileShell 的 rail）
   ```
2. 网格行列规则：`GridLayoutManager` 4 列；最后一行不足 4 张时，焦点不跳到空位；
   上/下优先保持同列（RecyclerView 默认行为即可）。
3. 焦点框：卡片 **3dp `ACCENT` 边框 + 4dp `ACCENT` 20% 外发光 + 1.02× 缩放**；
   用 foreground drawable 实现，不改 padding（避免布局抖动）。
4. 卡片行高 = 379dp（封面 287 + 标题 48 + meta 20 + 间距/内边距），行间距 18dp、行距 397dp；
   焦点滚动时保证**下一行露出 ≥24dp**，提示「还有内容」。
5. 操作：OK=打开（历史续播/收藏详情/下载项）；长按 OK（1.2s）=删除/取消收藏（与电视台直播页一致）；
   Back=回到全局导航；MENU=切换页签菜单（可选，非必须）。
6. TV 不在卡片上放「删除/♥」小按钮（焦点顺序会被打散）；触屏断点才显示右上角 24dp 圆钮。

### 8.1 页面层级

### 8.2 span / 卡片尺寸计算

```java
// 1) 全局可用宽度（与 MobileShell.render 的 tabletSideRail 判定一致）
float density = a.getResources().getDisplayMetrics().density;
int W = a.windowWidth();
boolean sideRail = W / density >= 640f;                  // W >= 640dp
float navScale = Prefs.clampNavScale(a.prefs.getInt(Prefs.NAV_SCALE_PERCENT, 100)) / 100f;
int railW = sideRail ? Math.round(20 + 72 * navScale) : 0;   // 8+12 内边距 + 72 栏
int Wc = W - railW;

// 2) 断点与边距
boolean tv = a.isTvDevice();
int sidePad = tv ? 24 : (W / density < 600 ? 16 : (W / density < 840 ? 20 : 24));
int gapH = tv ? 18 : (W / density < 600 ? 0 : (W / density < 840 ? 12 : (W / density < 1080 ? 14 : 16)));

// 3) span（手机列表 = 1）
if (W / density < 600 && !tv) {
    span = 1;                                // 列表行，行高 100
} else {
    int minCard = tv ? 172 : (W / density < 840 ? 140 : (W / density < 1080 ? 156 : 168));
    int available = Wc - sidePad * 2;
    span = Math.max(2, (int) Math.floor((available + gapH) / (minCard + gapH)));
    span = Math.min(span, tv ? 4 : 6);       // TV 最多 4 列，大平板最多 6 列
}

// 4) 卡片宽高（GridLayoutManager 下 item 宽 = (content - (span-1)*gapH) / span）
int cardW = (Wc - sidePad * 2 - (span - 1) * gapH) / span;
int coverH = Math.round(cardW * 1.5f);       // 2:3
int titleH = tv ? 48 : 42;
int metaH  = tv ? 20 : 18;
int cellH  = coverH + 10 /*封面-标题间距*/ + titleH + 4 + metaH + 10 /*底部内边距*/;

// 5) 应用
GridLayoutManager lm = new GridLayoutManager(a, span);
rv.setLayoutManager(lm);
rv.setPadding(sidePad, 0, sidePad, bottomInset);
// item 根：MATCH_PARENT × cellH；封面：MATCH_PARENT × coverH（2:3）；
// 标题：固定高 titleH、maxLines=2、ellipsize=END；meta：固定高 metaH。
```

### 8.3 卡片 Holder 复用

- 一个 `LibraryCardHolder` 同时服务网格与 TV（TV 设置 `setFocusable(true)` + 焦点 foreground）；
- 手机列表行独立 `LibraryRowHolder`（封面 56×80、标题 1 行、进度条、删除按钮）；
- 空状态/下载列表各一个 ViewHolder（`getItemViewType` 区分：0 列表/网格、1 下载、2 空状态）。
