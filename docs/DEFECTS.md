## 0. 状态与严重度定义

**状态**：`已修（代码确认，待真机验证）` → `已验证`（真机通过并留证据）／`回归失败`（重开）；`开放`；`待确认`（原始现象需 Lead/用户补充）。

**严重度**

| 级别 | 判定 | 对发布的影响 |
|---|---|---|
| P0 | 崩溃、数据丢失、无法启动、安全漏洞（未授权访问/任意写入） | 阻塞，不豁免 |
| P1 | 主流程不可用或严重体验退化（播放/直播/搜索/片库不可用） | 阻塞，除非 Lead 书面豁免 |
| P2 | 局部功能异常、明显 UI/规范偏差 | 可带风险发布，需登记处置 |
| P3 | 文案、轻微视觉、低概率问题 | 记录即可 |

### DEF-2002 直播注入脚本 1.8 s 无限重跑（P1，发热/卡顿）

- **证据（静态）**：`TvLive.java:1514-1522` 每 1800 ms `evaluateJavascript(INJECT_JS + fitJs())` 自续；`:1679` 起播 2.5 s 后启动；`:2201` 仅在关闭播放器时 `removeCallbacksAndMessages(null)`。注入脚本（`:2359-2387`）每次都会点击播放按钮、`muted=false; v.play()`，并重设 video 父容器固定定位、隐藏兄弟节点——持续 JS + 重排。
- **前置**：官方网页源可播；TV 或低端手机。
- **步骤**：①起播 ②连续播放 10 min（不操作）③每 2 min 记录一次 `dumpsys meminfo com.whalefall.movie` 与设备温度 ④切台 10 次后再记一次。
- **实际**：JS 持续执行、内存/温度随时间上升；低端设备可能出现掉帧、发热。
- **预期**：注入幂等且限次（如 5 次后停止），暂停/退后台停止；内存不持续增长。
- **证据**：10 min 录屏（画面掉帧）、`meminfo` 时间序列、切台后的 `meminfo`；TV 可用红外测温或系统温度显示。
- **判定**：内存持续单向增长或明显发热/掉帧 = 失败（具体阈值由 Lead 拍板）。
- **1.3.1 更新（2026-11-09）**：修复中——**inject 单例化 + 真实播放探针**（与 DEF-2010 同一方案）；验证方式见 `docs/VERIFY_1.3.1.md` V11（直播页停留 10 min 不发热/不卡顿，至少 5 min）；验证通过后本条状态置为「已验证」。

### DEF-2004 FTP 明文传输 + 6 位口令（P3，安全残余风险）

- **证据（静态）**：`MiniFtpServer.java:29-34` 每次启动生成 6 位数字口令；`:86-93` 仅接受回环/站点本地地址；`:104-116` 用户 `wf` + 口令鉴权；`:185-231` 鉴权后仍可 STOR/RETR/DELE。匿名问题已修（见 DEF-1013），但**通道为明文 FTP**，同网段可嗅探口令与文件内容，6 位数字口令在局域网内存在暴力窗口（每次打开后台重新生成，窗口有限）。
- **前置**：管理员后台已打开；同网段测试机；不使用个人文件。
- **步骤**：①面板记下 `ftp://<ip>:2121/（用户 wf / 密码 <6 位>）` ②同网段另一台设备抓包或直接尝试错误口令 5 次 ③用正确口令上传/下载/删除测试文件。
- **实际**：口令与数据明文传输；错误口令被 530 拒绝；正确口令可读写。
- **预期（可接受方案）**：默认关闭或改 HTTPS；只写不删；口令错误限速；面板明示「仅在可信网络使用」。
- **证据**：面板截图（口令脱敏后）、抓包/客户端记录、错误口令被拒截图。
- **判定**：能匿名访问或跨网段访问 = P0 失败；仅明文+正确口令可访问 = P3 已知风险。

### DEF-2010 直播已出画面但加载浮层不消失（P1，1.3.0 实测）

| 字段 | 内容 |
|---|---|
| 发现版本 | 1.3.0（13000）— **待用户确认**（用户 21:43 刚装包，版本以设备实际为准） |
| 设备形态 | M367FC 平板，横屏（Android 17） |
| 严重度 / 优先级 | **P1** / 1.3.1 首个修 |
| 关联用例 | `docs/VERIFY_1.3.1.md` V9；E2-S1 |
| 复现率 | 待用户补（当前 1/1 实测） |
| 前置条件 | 已进过电视台；任一预置频道 |
| 复现步骤 | ①电视台 → CCTV-2 财经 ②等画面已经播出 ③看画面中间的加载浮层 |
| 实际结果 | 画面已出帧/在播，浮层仍停在「正在连接 CCTV-2 财经 / 正在加载官方页面 80%」，不淡出、不消失 |
| 预期结果 | 画面出帧后 **1s 内浮层淡出**，且之后不再出现 |
| 日志线索 | 待用户补「设置 → 运行日志」直播相关行（可与 V9 一起提供） |
| 证据路径 | 用户截图 2026-11-09 21:43（待归档 `/sdcard/Download/DSH-Go/鲸落/verify/1.3.1/`） |
| 状态 | **已修待验证**（开发修复中） |
| 修复版本/提交 | 1.3.1（Lead 已定方案） |
| 验证记录 | 待 V9 真机验证后回填设备+日期+结论 |

**根因（Lead 代码定位，QA 静态核对）**：
- 浮层显隐只挂在 WebView 回调上：`TvLive.java:1597-1599` `onPageStarted` → `showLoading()`；`:1601-1603` `onPageFinished` → `hideLoading()`。
- 官方直播页进度可能停在 <100%（长连接、资源加载失败、重定向未收尾）→ `onPageFinished` 不触发，浮层一直留在画面上；「80%」就是 WebView 进度停住的直接表现。
- 页面内跳转/重定向会再次 `onPageStarted` 把浮层重新 `showLoading()`（`:1598`）；切分组/切台路径也会 `showLoading()`（`:1691`、`:2073`），之后若等不到新的 `onPageFinished`，浮层同样不消失。
- 本质：**用页面加载进度当播放状态**，与「画面是否真的出帧」脱钩。

**修复方案（Lead 已定，1.3.1）**：
1. **真实播放探针**：注入脚本检测 `<video>` 的 `readyState`/`currentTime>0`（真的在播才算成功），成功才 `hideLoading()`；
2. `progress>=100` 作为兜底隐藏条件（页面加载完成、视频稍晚出帧也能收浮层）；
3. **全屏时强制收起浮层**（全屏下不许再挡画面）；
4. **inject 单例化**（与 DEF-2002 一并修），避免重复注入、重复 `showLoading()`。

**判定**：画面已出帧而浮层仍可见 >1s = 失败（P1，阻塞 1.3.1 收口）。
